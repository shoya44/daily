# Daily 要件定義・設計仕様書

## 1. プロジェクト概要

| 項目 | 内容 |
| --- | --- |
| アプリ名 | Daily |
| 目的 | 面倒くさがりのための、必要な情報だけを簡単に記録・確認できるカレンダー/手帳風アプリ |
| 形式 | PWA（ホーム画面追加可能、オフライン起動対応） |
| 対象デバイス | iPhone（Safari）, PC（Chrome） |
| デザイン | ダーク・ミニマル・Apple/Linearライク |
| データ管理 | Supabase（無料プラン、メールアドレス認証あり、RLS適用） |

---

## 2. システム構成

- **F/E:** HTML5 / CSS3 / JavaScript (Vanilla JS, ES6+)
- **B/E:** PostgreSQL (Supabase)
- **Auth:** Supabase Auth (Email / Password)
- **外部API:** Open-Meteo API（天気情報取得）
- **祝日データ:** app.js 内埋め込み（2026〜2027年対応）

---

## 3. DB仕様（Supabase）

> 全テーブルで Row Level Security (RLS) を有効化し、`auth.uid() = user_id` のポリシーを設定。

### 3.1 events テーブル（予定・メモ）

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK, gen_random_uuid() | 予定ID |
| user_id | uuid | NOT NULL, auth.uid() | ユーザーID |
| date | date | NOT NULL | 予定の日付 (YYYY-MM-DD) |
| text | text | NOT NULL | 予定内容 |
| created_at | timestamptz | DEFAULT now() | 作成日時 |

### 3.2 work_records テーブル（日々の勤務形態）

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK, gen_random_uuid() | 記録ID |
| user_id | uuid | NOT NULL, auth.uid() | ユーザーID |
| date | date | NOT NULL | 対象日付 (YYYY-MM-DD) |
| status | text | NOT NULL, CHECK制限 | 勤務形態コード |
| updated_at | timestamptz | DEFAULT now() | 更新日時 |

- **CHECK値:** `office`, `remote`, `paid_full`, `paid_am`, `paid_pm`, `holiday_work`, `off`
- **複合UNIQUE制約:** `(user_id, date)`

### 3.3 settings テーブル（ユーザー設定）

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK, gen_random_uuid() | 設定ID |
| user_id | uuid | NOT NULL, UNIQUE, auth.uid() | ユーザーID |
| data | jsonb | NOT NULL | 設定データオブジェクト |

- **初期データ生成:** `handle_new_user()` トリガーにより新規登録時に自動作成
- **data 構造:**

```json
{
  "workDefaults": {
    "mon": "remote", "tue": "office", "wed": "office",
    "thu": "remote", "fri": "remote", "sat": "off", "sun": "off"
  },
  "garbageSchedule": [
    { "type": "燃えるゴミ", "weekdays": [1, 4], "weeks": [] },
    { "type": "プラスチック", "weekdays": [6], "weeks": [] },
    { "type": "資源", "weekdays": [2], "weeks": [] },
    { "type": "燃えないゴミ", "weekdays": [5], "weeks": [2, 4] }
  ],
  "weatherLocation": { "name": "東京", "lat": 35.68, "lon": 139.76 }
}
```

## 4. 画面仕様

### ① 認証画面 (`#screen-auth`)

- メールアドレス・パスワード入力フォーム
- 「ログイン」および「新規登録」ボタン
- エラー・通知メッセージ表示領域
- 認証成功時、自動的にメインアプリ画面を表示

### ② メイン画面 (`#screen-today`)

- **ヘッダー:** アプリ名「Daily」、今日の日付（月・日・曜日）
- **天気カード:** 天気アイコン、最高気温、天気説明（Open-Meteo APIより取得）
- **服装アドバイス:** 傘要否（降水確率≥50%）、服装目安（最高気温より判定）
- **勤務形態カード:** 当日の勤務形態バッジ（タップで変更モーダル）＋ 今週の出社日数カウント
- **ゴミの日カード:** 当日出すゴミの種類（対象なし時は「ゴミなし」）
- **予定カード:** 当日の予定リスト（タップで削除確認モーダル）
- **FAB（＋）:** 画面右下固定、タップで予定追加モーダル表示

### ③ カレンダー画面 (`#screen-calendar`)

- **月ナビゲーション:** 「前月」「次月」ボタン、「今日」移動ボタン
- **カレンダーグリッド:** 当月の日付グリッド（青ドット＝予定あり、黄ドット＝勤務形態変更あり）
- **選択日の詳細:** 日付タイトル、勤務形態ドロップダウン（リアルタイム変更可）、該当日の予定リスト

### ④ 設定画面 (`#screen-settings`)

- **勤務形態デフォルト:** 月〜日の曜日ごとのデフォルト勤務形態（タップで変更モーダル）
- **ゴミの日設定:** ゴミ種別ごとの曜日・週指定一覧表示
- **天気設定:** 取得地点（場所名、緯度、経度）の編集モーダル呼び出し
- **アカウント:** ログアウトボタン

> ※ 通知設定はV1スコープ外

## 5. 機能仕様・判定ロジック

### 5.1 勤務形態の判定フロー

1. 対象日付で `work_records` を検索 → 記録があればその `status` を採用
2. 記録がない場合、祝日リスト（HOLIDAYS）に存在するかチェック → 祝日なら `off`
3. 祝日でもない場合、`settings.workDefaults` の該当曜日の設定値を採用

### 5.2 ゴミの日判定ロジック

- 対象日付の「曜日番号(0=日〜6=土)」および「その月の第何回目の曜日か」を算出
  - 算出式: `floor((date - 1) / 7) + 1`
- `garbageSchedule` の各条件をチェック:
  - `weekdays` に該当曜日が含まれるか
  - `weeks` が空（毎週）、または算出された第N回目が含まれるか
- 両方を満たすゴミ種別を配列として抽出し表示

### 5.3 服装判定ロジック

| 条件 | 表示 |
|---|---|
| 最高気温 ≥ 28°C | 半袖で快適 |
| 最高気温 ≥ 22°C | 半袖＋薄手の上着 |
| 最高気温 ≥ 18°C | 長袖シャツで快適 |
| 最高気温 ≥ 12°C | 長袖＋カーディガン |
| 最高気温 < 12°C | コートが必要 |
| 降水確率 ≥ 50% | 傘必要 |

## 6. 非機能・運用仕様

### オフライン挙動（V1制約）

- Service Worker により静的ファイル（HTML/CSS/JS/アイコン）をローカルキャッシュ
- オフライン下でもアプリの起動・閲覧が可能
- オフライン中の書き込み操作はV1では制限し、トースト通知（「オフラインのため変更できません」）を表示

### 祝日データの更新管理

- `app.js` 内の HOLIDAYS オブジェクトに埋め込み
- 年1回（年末年始等）に翌々年分を手動追加更新
